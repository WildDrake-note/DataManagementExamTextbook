# 継続課題

この文書は、初版で未完了の作業を個別に着手できる単位へ分けたバックログです。GitHub Issueを作成するときは、各見出しを1件のIssueとして転記します。

## 優先度A：公式情報への追随

### 正式シラバス・試験要綱との差分反映

- IPAのシラバス掲載ページを定期確認する。
- Ver.0.1以降が公開されたら項目単位で差分を作る。
- `docs/guide/syllabus-map.md`、章本文、用語集、変更履歴を更新する。
- 試験時間・問題数・合格基準などは正式発表があるまで推測で記載しない。

**完了条件**：基準版、確認日、変更項目、影響ファイルが記録されている。

### 参考資料レジストリの機械可読化

- 組織、資料名、URL、版、公開日、最終確認日、文書状態、利用条件、対応シラバス項目をYAMLで管理する。
- リンク切れと改版候補を定期確認する仕組みを追加する。

**完了条件**：参照一覧をYAMLから検証でき、固定PDFと案内ページを対応付けられる。

## 優先度B：本文の拡充

### 科目A細目の網羅性レビュー

- シラバスの全用語例を一覧化する。
- 本文、用語集、未掲載の三状態を記録する。
- 未掲載語を重要度と前提関係で優先順位付けする。

**完了条件**：全用語例に状態と参照先がある。

### 統計・業務分析の例題追加

- 確率、順列・組合せ、正規分布、分散・標準偏差、回帰、相関、推定、仮説検定を追加する。
- 線形計画法、需要予測、パレート図、クラスタ分析の初学者向け例を追加する。
- 計算だけでなく、前提と誤解釈を問う。

**完了条件**：シラバスの統計・業務分析用語ごとに解説と1問以上の演習がある。

### データ基盤・AI利活用の例追加

- ETL/ELT、仮想化、データファブリック、セマンティックレイヤーを比較する独自図を作る。
- 識別AI、生成AI、AIエージェントで異なるデータ統制をケース化する。

**完了条件**：仕組みの違い、適用条件、リスクを説明する図と演習がある。

## 優先度B：演習の拡充

### 科目A型問題集

- 各章に四肢択一を5問以上作成する。
- 「最も適切」と組合せ問題を含める。
- 全選択肢に正誤理由を付ける。

### 科目B型ケース集

- 公式サンプルとは異なる独自事例を作る。
- 適切な取扱い、意思決定と改善、組織文化、PoCの4大項目を網羅する。
- ルール、データ定義、実データ、役割表を読み合わせる形式を含める。

**完了条件**：科目Bの全小項目に少なくとも1ケースが対応する。

## 優先度C：公開品質

### 図表・アクセシビリティ

- Mermaidまたは独自SVGでライフサイクル、役割、品質改善、分析プロセスを図示する。
- 代替テキスト、色以外の区別、印刷時の可読性を確認する。

### GitHub Pages公開

- MkDocs Materialの依存関係を固定する。
- GitHub Actionsで厳格ビルドとPages公開を行う。
- 公開URL、版、最終更新日をREADMEへ追加する。

### 内容レビュー

- データマネジメント実務者による技術レビュー
- 統計に関するレビュー
- 法務・個人情報・著作権に関する表現レビュー
- 日本語校正と用語統一

**完了条件**：指摘と対応結果がPull Requestまたはレビュー記録に残っている。
