# 図表で振り返るデータマネジメント

このページは、第1〜12章で学んだ概念を横断して復習するための整理表です。用語だけを暗記するのではなく、業務上の問いに対して、どの観点と章を使うかを確認してください。

## 1. データが価値へ変わる全体像

```text
┌──────────── 組織の目的・業務課題 ────────────┐
│                                             │
│  方針・責任・監視                           │
│  ┌────── データガバナンス ──────┐           │
│  │                              │           │
│  │ 生成 → 保管 → 処理 → 活用 → 廃棄        │
│  │        データライフサイクル              │
│  │          │       │       │              │
│  │       品質管理  メタデータ  セキュリティ │
│  │          └───────┼───────┘              │
│  └──────────────────┼───────────────────────┘
│                     ↓
│        データ基盤 → 分析・AI → 洞察
│                     ↓
│             意思決定 → 実行 → 検証
│                     ↓
│              教訓・組織文化・改善
└─────────────────────────────────────────────┘
```

ガバナンスは外側から活動を止める仕組みではありません。目的、意思決定権、責任、監視を明確にし、ライフサイクル全体で品質、意味、安全性を維持するための枠組みです。分析やAIは、その枠組みの中で信頼できるデータを利用し、意思決定と改善へつなげます。

## 2. 業務上の問いと参照章

| 業務上の問い | 主な確認観点 | 参照章 |
|---|---|---|
| この数値は何を意味するか | 定義、粒度、範囲、基準日、責任者 | 第1・5・6章 |
| どれが最新版・正本か | 生成元、更新、版、保管場所、SSOT | 第1・2・8章 |
| 誰が決め、誰が直すか | オーナー、スチュワード、DMO、IT、利用者 | 第3章 |
| 分析に使える品質か | 正確性、完全性、一貫性、一意性、最新性 | 第4章 |
| どこから来てどこへ流れるか | リネージ、データフロー、変換、提供先 | 第5・6章 |
| 結合してよいか | 識別子、粒度、意味、時点、利用条件 | 第6章 |
| 利用してよいか | 目的、権限、機密区分、法令、契約、倫理 | 第7章 |
| AIへ入力・実行させてよいか | 入力条件、出力検証、権限、人間承認、停止 | 第8章 |
| どのデータと分析を選ぶか | 問い、仮説、生成背景、比較可能性、バイアス | 第9章 |
| 結果をどう行動へ変えるか | 示唆、優先順位、効果、リスク、実現可能性 | 第10章 |
| 組織へどう定着させるか | 対話、制約、成功・失敗共有、心理的安全性 | 第11章 |
| 新技術を導入すべきか | 情報源、適合性、PoC、費用、運用、撤退条件 | 第12章 |

## 3. 問題を発見したときの判断手順

```text
事実を確認する
  ├─ 何が起きたか
  ├─ 期待する定義・規則は何か
  └─ 件数、期間、影響範囲はどこまでか
        ↓
責任と緊急度を確認する
  ├─ データオーナーは誰か
  ├─ 事故対応が必要か
  └─ 誰へ報告・相談するか
        ↓
暫定対応を行う
  ├─ 影響拡大を止める
  ├─ 承認・期限・対象を記録する
  └─ 元データと証拠を保全する
        ↓
原因を分析して恒久対応を行う
  ├─ 人だけでなく、定義・手順・システムを見る
  ├─ 入力制御、責任、教育、監視を見直す
  └─ メタデータとルールを更新する
        ↓
効果を再測定し、教訓を共有する
```

| 段階 | 成果物の例 | 避けるべき行動 |
|---|---|---|
| 事実確認 | 問題レコード、再現条件、影響一覧 | 推測を事実として報告する |
| 暫定対応 | 除外・保留・権限遮断の記録 | 根拠なく削除・上書きする |
| 原因分析 | 発生工程、原因候補、検証結果 | 担当者個人の注意不足だけで終える |
| 恒久対応 | ルール、入力制御、責任分担の変更 | 毎回の手修正を恒久策と呼ぶ |
| 効果確認 | 対策前後の指標、副作用、残課題 | 都合のよい指標だけを選ぶ |

## 4. データ、メタデータ、ルール、証拠の違い

| 種類 | 例 | 主な役割 | 誤解しやすい点 |
|---|---|---|---|
| 実データ | 顧客ID、注文金額、更新日時 | 業務上の事実・記録を表す | 値が存在しても正しいとは限らない |
| ビジネスメタデータ | 売上の定義、オーナー、利用目的 | 意味と責任を説明する | 列名だけでは業務定義にならない |
| テクニカルメタデータ | 型、桁、キー、変換仕様 | 実装と構造を説明する | 型一致は意味一致を保証しない |
| オペレーショナルメタデータ | 最終更新、処理件数、ジョブ結果 | 鮮度と運用状態を説明する | 定義上の更新頻度と実績は別である |
| ルール | 必須入力、保存期間、承認条件 | 許容状態と行動を定める | ルールがあっても遵守確認が必要である |
| 証拠 | ログ、承認記録、評価結果 | 実施事実と判断根拠を示す | 成功した結果だけでは十分でない |

## 5. 分析結果を読むための四層

```text
[測定]  何を、どの単位・期間・方法で記録したか
   ↓
[比較]  何と何を、同じ条件で比べたか
   ↓
[解釈]  交絡、逆因果、偏り、欠測を検討したか
   ↓
[判断]  効果、費用、リスク、実現可能性をどう評価したか
```

| 層 | 確認質問 | 典型的な誤り |
|---|---|---|
| 測定 | 分母、粒度、対象期間、除外条件は何か | 件数と割合を混同する |
| 比較 | 比較群や基準値の条件はそろっているか | 前後差をすべて施策効果とみなす |
| 解釈 | 第三の要因や選択バイアスはないか | 相関を因果と断定する |
| 判断 | 統計的差と業務上の重要性を分けたか | p値や平均値だけで導入を決める |

## 6. AI活用で追加される確認点

| 対象 | 入力 | 出力 | 実行・運用 |
|---|---|---|---|
| 識別AI | 学習データの代表性、ラベル、利用権限 | 誤判定、対象群ごとの性能、説明 | 判断支援と自動決定の境界、人間確認 |
| 生成AI | 機密情報、個人情報、著作物、保存・学習条件 | 誤情報、偏り、出典、著作権、形式 | 利用目的別の検証、ログ、再現条件 |
| RAG | 文書の正本、権限、更新、分割 | 検索漏れ、誤取得、引用不一致 | 情報源から回答までの追跡、評価 |
| AIエージェント | 利用可能なデータとツール | 計画・判断の誤り、例外 | 最小権限、承認、上限、停止、監査ログ |

```text
低い自律性                                      高い自律性
閲覧のみ → 下書き作成 → 人の承認後に実行 → 条件内で自律実行
   │            │               │                  │
小さい影響   内容の検証      実行直前の確認     上限・停止・監視を強化
```

自律性を高めるほど、モデルの性能だけでなく、ツール権限、実行上限、例外処理、停止手段、監査可能性が重要になります。

## 7. PoCから本番導入まで

```text
課題 → 仮説 → 成功・中止条件 → 小規模検証 → 結果・限界
                                              ↓
      中止 ← 追加検証 ← 条件付き判断 → 段階導入 → 本番監視
```

| 判断材料 | PoCで確認する例 | 本番前に追加確認する例 |
|---|---|---|
| 業務効果 | 時間、品質、顧客影響 | 長期間・全対象での再現性 |
| データ | 取得可能性、品質、利用条件 | 継続取得、変更、保持・廃棄 |
| 技術 | 精度、性能、障害時挙動 | 容量、監視、復旧、保守 |
| 人・運用 | 作業負担、承認、例外処理 | 教育、責任分界、問い合わせ対応 |
| 費用 | 試行費用、概算便益 | 移行、連携、監視、教育を含む総費用 |
| リスク | 重大な誤り、情報管理 | 残余リスク、停止・撤退手順 |

「技術が動いた」はPoCの一結果にすぎません。目的とした業務効果が得られ、リスクと運用負担を許容でき、費用を説明できるかを分けて判断します。

## 8. 復習方法

1. 業務場面を一つ選び、全体図の各要素がどこにあるか説明する。
2. 問題対応図に沿って、事実、責任、暫定対応、恒久対応を分ける。
3. 分析結果を測定・比較・解釈・判断の四層で読み直す。
4. AIやPoCでは、通常のデータ管理に何が追加されるか説明する。
5. 説明できない箇所を対応する章と科目Bケースで復習する。
