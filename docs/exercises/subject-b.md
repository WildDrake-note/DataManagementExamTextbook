# 科目B型ケース演習

以下は本書独自の問題です。IPA公式サンプル問題の転載・改変ではありません。最初に本文だけを読み、各ケースについて「目的・規範・事実・差異・影響・責任主体・暫定対応・恒久対応」を整理してください。

## ケース1：商品分類コード

卸売会社A社では、商品マスターを商品部が管理し、データオーナーを商品部長、日常の登録を商品管理担当、システム運用をIT部門が担っています。全社規程では、商品分類コードはデータカタログのコード一覧に従い、変更時は商品部が定義を更新するとされています。

分析部が仕入分析を行ったところ、カタログにない分類コード `X9` が全商品の3%に登録されていました。調査すると、商品管理担当が「分類未決定」を表すため半年前から入力していました。来週の経営会議では分類別在庫額が必要です。

### 問1

品質問題の恒久対応を主導すべき役割として最も適切なものはどれですか。

1. 分析部
2. 商品部のデータオーナー
3. IT部門
4. 経営会議の事務局

### 問2

来週の分析に向けた暫定対応として必要な事項を三つ挙げてください。

### 解答・解説

**問1：2。** 商品分類の業務定義と品質について意思決定する責任は商品部のデータオーナーにあります。IT部門は入力制御の実装を担う可能性がありますが、業務上 `X9` を正式値にするか、別の方法を取るかを単独では決めません。

**問2の例：** `X9` の意味と対象を商品部へ確認する、経営会議の集計での扱いを承認する、補正・除外・注記の規則と影響額を記録する。暫定分類を行う場合、分析結果の前提と説明責任を明確にします。

恒久対応では、未決定状態を正式コードとして管理するか、登録前の承認を設けるか、入力チェックを行うかを決め、実データとカタログを整合させます。

## ケース2：会員データの統合

サービス会社B社には、予約システムと請求システムがあります。両方に会員IDがありますが、予約システムは登録順の数値、請求システムは契約番号を使っています。どちらも各システム内では一意です。メールアドレスは予約側で任意、請求側で必須です。経営企画部は会員別の利用額を今月中に集計したいと考えています。

### 問1

最も根本的な課題を説明してください。

### 問2

メールアドレスで結合する場合に確認すべきことを四つ挙げてください。

### 解答・解説

**問1：** システム横断で同一会員を識別する共通識別子または管理された対応関係がないことです。IDの型や見た目ではなく、識別範囲の不一致が根本課題です。

**問2の例：** 欠損率、一意性、本人確認の程度、更新・変更、大小文字や空白などの正規化、家族等による共有、利用目的・権限、誤結合・未結合の評価。メールアドレス結合は暫定手段になり得ますが、精度と除外対象を明示します。

恒久対応として、全社会員ID、マスターデータ、識別子対応表の管理責任と更新プロセスを検討します。

## ケース3：生成AIによる問い合わせ要約

C社のサポート部は、問い合わせ履歴を生成AIで要約し、製品改善へ利用するPoCを計画しています。履歴には顧客名、連絡先、契約内容、自由記述が含まれます。担当者は無料の外部AIサービスを使い、100件を試す予定です。会社には「顧客情報を未承認の外部サービスへ入力しない」という規程があります。

### 問1

現計画のまま実施してはいけない主な理由を説明してください。

### 問2

安全なPoCへ組み直すための検討事項を挙げてください。

### 解答・解説

**問1：** 顧客情報を未承認サービスへ入力する計画が社内規程に反し、個人情報・契約・機密性・サービス側の保存や学習利用に関するリスクが未評価だからです。PoCであることは規程を無効にしません。

**問2の例：** データオーナー・法務・セキュリティ部門への相談、承認済み環境、疑似データまたは適切な匿名化、入力最小化、保存・学習条件、アクセス権、削除、ログ、評価基準、人間レビュー、停止条件。

評価では要約の正確さだけでなく、重要情報の欠落、誤情報、偏り、確認時間、費用、本番運用上の責任も確認します。

## 自己採点の観点

- 事例に書かれた規程と、自分の常識を混同していないか。
- システム管理者とデータ内容の責任者を区別したか。
- 形式上の問題と、識別・責任・定義の根本問題を区別したか。
- 暫定対応に期限・承認・記録・影響説明を含めたか。
- 恒久対応が発生原因へ向いているか。
