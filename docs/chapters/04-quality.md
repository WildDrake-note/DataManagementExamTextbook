# 第4章 データ品質管理

## 学習目標

- 目的に応じたデータ品質特性を選べる。
- プロファイリングで欠損、重複、異常、形式不整合を確認できる。
- 予防、検出、是正、継続改善を区別できる。
- 品質問題の影響と原因を整理し、適切な相手へ報告できる。

**シラバス対応**：科目A・重点分野「データ品質管理」、科目B 1-4、2-2。

## 1. 品質は目的への適合性

絶対的に「高品質」なデータがあるのではなく、利用目的に必要な品質を満たすかが重要です。配送には住所の正確性と最新性が必要で、月次傾向の概算には多少の遅延を許容できるかもしれません。品質要求は業務影響と費用の均衡で決めます。

## 2. 主な品質特性

| 特性 | 問いの例 |
|---|---|
| 正確性 | 現実の対象や正しい基準値を表しているか |
| 完全性 | 必要な値・レコードが欠けていないか |
| 一貫性 | データ間や時点間で矛盾していないか |
| 一意性 | 同じ対象が重複登録されていないか |
| 最新性 | 利用時点に必要な新しさか |
| 妥当性 | 型、桁、範囲、コードなどの規則に合うか |
| 信憑性 | 出所と生成過程を信頼できるか |
| 機密性 | 許可された者だけが利用できるか |

シラバスの用語例と、科目B技能例に現れる観点には表現差があります。実務では目的に応じて品質観点を定義し、名称だけでなく測定方法を明確にします。

## 3. 品質ルールと測定

良い品質指標は測定可能で、業務目的と関係し、関係者が受容でき、改善主体が制御可能な要素へつながります。**品質特性 → 測定量 → 判定基準**の順に具体化します。

例：

- 必須項目のNULL率が0.1%未満
- 顧客IDの重複件数が0件
- 商品コードが有効なマスター値に一致する割合が99.9%以上
- 更新期限内に更新されたレコードの割合が98%以上

件数だけでなく分母、対象期間、除外条件、判定時点を定義します。

| 品質特性 | 測定量の例 | 計算例 | 判定基準の例 |
|---|---|---|---|
| 完全性 | 必須値充足率 | 必須値が入った件数 ÷ 対象件数 | 99.9%以上 |
| 一意性 | 重複違反率 | 重複対象件数 ÷ 対象件数 | 0.1%未満 |
| 妥当性 | 有効コード率 | マスターに存在するコード件数 ÷ 非NULL件数 | 100% |
| 最新性 | 期限内更新率 | 期限内に更新した件数 ÷ 更新対象件数 | 98%以上 |

同じ「重複件数」でも、重複した行数、重複グループ数、重複した対象の数では値が変わります。式と数え方を定義しなければ、部門間で比較できません。また、プロファイリングで形式や分布は調べられても、住所や金額が現実と一致するかという**正確性**は、正本、伝票、本人確認済み情報などとの照合が必要です。

### 3.1 実行可能な品質ルールの設計

「顧客データを正しくする」のような目標だけでは、検査も是正もできません。品質ルールは、少なくとも対象、条件、期待値、測定方法、判定時点、例外、違反時の行動を含めます。

| 設計要素 | 決める問い | 注文データの例 |
|---|---|---|
| 対象 | どの項目・レコード・期間か | 国内向け確定注文の配送希望日 |
| 適用条件 | どの条件で規則を適用するか | 店頭受取と予約商品を除く |
| 期待値 | 何を満たせばよいか | 注文日以降かつ注文日から30日以内 |
| 測定方法 | 分子・分母をどう数えるか | 条件違反注文数 ÷ 適用対象注文数 |
| 判定時点 | いつ値を固定して判定するか | 注文確定時と出荷バッチ開始前 |
| 例外 | 誰が、何を根拠に認めるか | 災害対応注文を物流責任者が期限付き承認 |
| 違反時の行動 | 停止、警告、隔離、報告のどれか | 確定を停止し、入力者へ理由を表示 |

ルールは厳しいほどよいわけではありません。業務上正当な例外まで拒否すると、担当者が架空値を入力して制御を回避することがあります。一方、警告だけで続行できる設計では、重要項目の欠損を防げない場合があります。違反による影響と、誤って正常データを止める影響の両方を比較して、停止、警告、事後確認を使い分けます。

### 3.2 指標が示さないもの

測定値には限界があります。「ルール適合率100%」でも、ルール自体が業務目的に合っていなければ高品質とはいえません。郵便番号がすべて7桁でも、別人の住所なら妥当性は満たしても正確性は満たしません。

| 測定上の限界 | 起きる誤解 | 補完する確認 |
|---|---|---|
| サンプリング | 未抽出部分にも同じ品質があるとみなす | 抽出方法、標本数、偏り、信頼範囲を示す |
| 集計値 | 少数の重大違反が平均に埋もれる | 重要顧客・高額取引など影響別に層別する |
| 代理指標 | 形式適合を現実との一致と誤認する | 正本や外部基準との照合を組み合わせる |
| 測定遅延 | 月末値を現在の状態だと誤認する | 測定時刻とデータ更新時刻を表示する |
| 除外条件 | 難しいレコードを除外して指標が良く見える | 除外件数、理由、全体への影響を併記する |

したがって、指標には値だけでなく、対象期間、母集団、算式、データ取得時刻、除外条件、測定上の制約を添えます。前月との比較では、ルールや母集団が変わっていないかも確認します。

## 4. データプロファイリング

プロファイリングは、実データの特徴を機械的・統計的に確認する活動です。

- 件数、NULL数、ユニーク数
- 最小・最大、平均、分布
- 文字数、型、パターン
- コード値別件数
- 重複候補
- 項目間の依存関係
- 時系列での急変

カタログ上で「NULL不可」と書かれていても、実データを確認するとNULLが存在する可能性があります。定義と実態の両方を調べます。

## 5. クレンジングと注意点

代表的な処理は、欠損値の補完・除外、外れ値・異常値の修正、重複排除、表記ゆれ統一です。ただし、値を変更すれば必ず品質が上がるわけではありません。

- 外れ値は入力誤りではなく、重要な事象かもしれない。
- 欠損補完は推定値であり、事実値と区別が必要。
- 名寄せの誤判定は別人を同一人物として結び付ける危険がある。
- 加工後データには、ルール、実施者、時点、元データへの追跡性が必要。

## 6. 継続的プロセス

1. **計画**：品質要求、指標、役割、測定方法を定める。
2. **制御**：入力チェック等で規則からの逸脱を防止・検出する。
3. **保証**：プロセスと結果が要求を満たすか確認する。
4. **改善**：原因を除き、再発防止と効果測定を行う。

```text
利用目的・業務影響
        ↓
品質要求 → 品質ルール → 測定・監視 → 問題の検知
   ↑                                  ↓
効果の再評価 ← 恒久対策 ← 原因分析 ← 暫定対応
```

暫定対応は、誤った請求を止める、問題レコードを分析対象から隔離するなど、影響拡大を防ぐ処置です。恒久対策は、入力画面の制御、コード体系の統一、更新手順の変更など、発生原因を除く処置です。両者を混同すると、緊急対応が遅れたり、同じ問題が再発したりします。

クレンジングは是正処置です。入力規則、マスター管理、教育、システム制御などの予防措置がなければ、同じ問題が再発します。

### 6.1 工程に置くコントロールポイント

品質管理は最終レポートだけで行うより、データが生成・移動・変換される各工程で行う方が、原因を特定しやすく手戻りも小さくなります。ただし、同じ検査を無目的に重複させるのではなく、工程ごとの故障の仕方に合わせます。

```text
[入力・生成] ----> [連携] ----> [変換・統合] ----> [提供・利用]
    │                 │              │                 │
 必須・範囲検査    件数・形式検査   参照整合・重複検査   鮮度・集計照合
    │                 │              │                 │
 その場で予防      隔離して再送     変換ログへ記録      注記・公開停止
    └──────────── 違反記録と原因情報 ────────────┘
                              │
                              v
                     傾向分析・恒久対策
```

| コントロールポイント | 適した検査 | 利点 | 注意点 |
|---|---|---|---|
| 入力時 | 必須、型、範囲、候補値 | 誤りを発生源で防ぎ、入力者が修正できる | 正当な例外を拒否しない設計が必要 |
| システム間連携時 | 件数照合、スキーマ、チェックサム、遅延 | 欠落・重複・形式変更を境界で検知できる | 送信側と受信側の件数定義をそろえる |
| 変換・統合時 | 参照整合、名寄せ確信度、変換前後合計 | 加工による品質劣化を見つけられる | 元からある誤りと加工で生じた誤りを分ける |
| 提供前・利用時 | 更新時刻、重要集計、利用目的別基準 | 誤った意思決定への波及を止められる | ここだけに頼ると修正費用が大きい |

予防制御ですべてを止められない場合は、検出制御と是正手順を組み合わせます。たとえば外部から受け取るデータを送信元で制御できなくても、受信時に隔離し、契約上の再送手順へつなげられます。

### 6.2 根本原因分析の進め方

根本原因分析では、「誰が間違えたか」より「どの条件が問題を繰り返し発生させたか」を調べます。次の順序で進めると、推測だけの対策を避けられます。

1. 問題を、対象、期間、期待値、実測値、影響で具体化する。
2. 最初に異常が現れた工程を、入力・連携・変換・提供の記録から絞る。
3. 人、手順、システム、データ定義、外部条件の観点で原因候補を出す。
4. ログ、再現試験、変更履歴、関係者への確認で候補を検証する。
5. 確認した原因に対応する恒久対策を選び、担当、期限、効果指標を決める。
6. 対策後に同じ条件で再測定し、再発や別工程への副作用を確認する。

「なぜ」を繰り返す方法や原因・結果を分類する図は、候補を広げるために役立ちますが、回数を満たせば根本原因になるわけではありません。たとえば「担当者が入力しなかった」で止めず、画面上で任意項目だったのか、定義が伝わっていなかったのか、繁忙時の代替手順がなかったのかを証拠で確認します。教育だけを対策にするより、入力制御や手順変更など、発生条件を変える対策を優先します。

## 7. 原因と影響の整理

品質問題を見つけたら次を整理します。

- 対象データと期間
- 期待する規則と実際の差
- 件数・割合・分布
- 影響するレポート、顧客、業務
- 発生工程と推定原因
- データオーナーと関係部門
- 暫定対応、恒久対応、期限

**実例：配送先住所の欠損**

配送予定500件のうち20件で住所の市区町村が欠損していたとします。欠損率4%だけを報告して終わりにせず、当日発送分が何件か、特定の受付経路に集中しているか、元伝票には値があるかを確認します。当日発送分を保留して確認するのが暫定対応、受付画面の必須チェックと連携エラー監視を追加するのが恒久対策です。対策後は同じ指標を再測定し、改善したかを確認します。

### 7.1 品質コストと業務影響の均衡

品質改善には、予防・測定・修正の費用がかかります。一方、放置にも、再作業、誤請求、配送失敗、顧客離反、規制対応などの費用があります。すべての項目を100%にするのではなく、失敗時の影響と検査・改善費用を比較して優先順位を付けます。

| 費用・影響 | 内容 | 見積り例 |
|---|---|---|
| 予防費用 | 入力制御、標準化、教育、マスター整備 | 開発工数、運用担当時間 |
| 評価費用 | プロファイリング、照合、監視、監査 | 検査件数、ツール費、確認時間 |
| 内部失敗費用 | 利用前に見つけた誤りの修正・再処理 | 再送、手修正、処理遅延 |
| 外部失敗費用 | 顧客や意思決定へ波及した後の損失 | 返金、再配送、逸失利益、信用低下 |

金額化しにくい法令違反、生命・安全、信用への影響は、単純な期待金額だけで切り捨てません。最低限守るべき基準を先に満たし、その上で費用対効果を比較します。また、平均損失が小さくても、まれに極端な損害が生じる項目には強い制御が必要です。

### 7.2 事業例：請求先口座の品質改善

法人向けサービスで、月1万件の請求のうち60件が口座情報不備で自動引落しに失敗し、1件当たり15分の確認作業と入金遅延が発生しているとします。

1. 「口座番号が所定桁数」という妥当性だけでなく、「金融機関・支店コードが有効」「口座確認済み」というルールを分けて測る。
2. 失敗60件を受付経路別に層別すると、50件が紙申込の転記に集中していることが分かった。全体失敗率0.6%だけでは、この集中は見えない。
3. 請求直前には未確認口座を隔離して担当者へ通知し、誤請求を防ぐ。これは検出と暫定対応である。
4. 紙申込の二重転記をやめ、読み取り後に担当者が原票と照合する画面を導入する。さらに、登録時に金融機関マスターを参照する。これは発生工程への恒久対策である。
5. 導入費用と、毎月の確認工数、入金遅延、顧客対応費を比較する。すべての顧客への高額な外部照合ではなく、紙申込経路から優先して改善する。
6. 対策後は失敗率だけでなく、誤って正常口座を止めた件数、確認時間、入金遅延日数も測る。

この例では、違反率を下げるだけでなく、問題が集中する工程に制御を置き、副作用と費用も評価しています。単一指標だけを目標にすると、厳しい判定で正常な請求まで停止し、かえって業務影響を増やす可能性があります。

## 確認問題（本書オリジナル・全4問）

### 問1

注文金額に通常の100倍の値が1件あります。直ちに削除することが不適切な理由を説明してください。

**解答例：** 本当に大口注文である可能性があり、統計的な外れだけで誤りとは断定できません。元伝票、単位、通貨、入力履歴などを確認し、業務ルールに基づいて異常値か正当値かを判断します。修正・除外した場合は根拠と影響を記録します。「平均から遠い値はすべて削除する」という対応は、重要な実績を失い、分析を都合よく変えるため不適切です。

### 問2

必須項目の充足率が99%でした。品質が十分か判断するために追加で必要な情報を挙げてください。

**解答例：** 対象項目、分母、期間、除外条件、要求水準、欠損が集中する業務・顧客、欠損による影響を確認します。救命や請求に必須の項目と、参考項目では許容水準が異なります。「99%は高い数字だから十分」とする判断は、残り1%の業務影響を無視するため不適切です。

### 問3

毎月同じ表記ゆれをクレンジングしています。継続的改善として次に行うべきことを説明してください。

**解答例：** 発生元、入力経路、コードや表記ルール、担当者、システム制御を調べ、選択式入力やマスター参照などの予防策を検討します。実施後は表記ゆれ率を再測定します。クレンジング作業だけを増やす方法は、原因を残したまま費用と誤修正リスクを継続させるため不十分です。

### 問4：測定限界とコントロール設計

審査システムで「本人確認番号の形式適合率100%」が3か月続いたため、担当者は提供前の本人照合を廃止して入力時の桁数チェックだけにしたいと提案しました。この提案を評価し、適切な対応を説明してください。

**解答例：** 形式適合率100%だけでは、番号が実在するか、申請者本人のものか、転記時に別人の有効番号へ置き換わっていないかは分かりません。まず、入力時の桁数チェックが保証する妥当性と、提供前照合が保証する正確性・本人との対応を分けます。誤りの件数と影響、照合費用、法令・契約上の要求、過去の検出実績を確認し、必要なら全件照合、リスクの高い案件の重点照合、信頼できる情報源との自動照合を選びます。制御を変更する場合は、対象、根拠、残留リスク、監視指標、見直し時期を承認・記録します。

**理由：** 一つの指標は、定義された規則への適合しか示しません。形式上有効な誤番号は桁数チェックを通過するため、正確性を必要とする業務では別のコントロールが必要です。一方、既存照合を無条件に続けるのではなく、失敗時の影響と費用を比較し、より効率的な制御へ置き換えられるかを検討することも品質管理です。

**よくある誤りと不適切な理由：** 「100%が続いたので品質問題はない」と結論付けるのは、妥当性を正確性と取り違えています。反対に、「品質は重要だから人手で永久に全件二重確認する」とするのも、費用、副作用、自動化の可能性を評価しておらず不十分です。

## まとめ

- 品質は利用目的への適合性で評価する。
- 定義だけでなく実データをプロファイリングする。
- クレンジングだけで終わらず、原因への恒久対策と効果測定を行う。
