# 第10章 意思決定と継続的改善

## 学習目標

- 分析結果を課題、要因、示唆、対応案へ結び付けられる。
- 重要度、緊急度、効果、実現可能性で対応案を比較できる。
- 目標値と実績値の差を検証し、改善へつなげられる。
- 分析条件と意思決定過程を再利用可能に記録できる。

**シラバス対応**：科目A「業務分析」、科目B 2-3～2-5。

## 1. 分析結果と洞察

「解約率が8%だった」は結果です。洞察は、業務課題と関連付け、行動に必要な意味を整理したものです。

```text
結果 → 解釈 → 要因候補 → 示唆 → 対応案 → 意思決定
```

例：特定プランの契約初月に解約が集中しているという結果から、導入説明や期待との不一致を要因候補として挙げ、初月支援の改善を対応案とします。ただし、因果が確認されていないなら候補として表現します。

## 2. 説明に含める内容

- 解決したい課題と問い
- 対象データ、期間、範囲、品質
- 集計・分析方法と前提
- 主な結果と不確実性
- 要因候補と反証
- 業務上の意味
- 対応案、期待効果、リスク
- 判断に必要な追加情報

数値だけでなく、誰が何を決めるための情報かを意識します。

## 3. 対応案の優先順位

| 観点 | 問い |
|---|---|
| 重要度 | 解決しない場合の影響は大きいか |
| 緊急度 | 期限や被害拡大の可能性はあるか |
| 期待効果 | 課題指標をどの程度改善できるか |
| 実現可能性 | 人、費用、技術、権限は確保できるか |
| リスク | 法務、倫理、品質、運用への副作用は何か |
| 可逆性 | 失敗時に戻せるか |

点数化は議論を助けますが、重大な法令違反リスクを平均点で相殺してはいけません。必須条件と比較条件を分けます。

## 4. AI分析結果の確認

AIを用いた場合も、利用データの範囲、対象期間、項目、前処理、分析前提、出力整合性を確認します。専門的なモデル評価が必要なら、データサイエンティストや主管組織と協働します。AIが出した説明を、検証なしに原因とみなしてはいけません。

## 5. 取組結果の検証

実行前に成功条件を決めます。

- 目標指標と基準値
- 期待する改善幅
- 測定期間
- 対象・比較対象
- 副作用を確認する指標
- 中止・見直し条件

実施後は目標値と実績値の差を確認し、差の原因を整理します。未達でも、仮説が否定されたことや実行上の障害が分かったことは学習成果です。

## 6. 定量・定性の両面

処理時間が20%短縮しても、入力負担や顧客体験が悪化しているかもしれません。数値で測れる成果と、現場観察・利用者意見などの定性的情報を組み合わせます。ただし、印象だけで全体傾向を代表させないようにします。

## 7. 教訓を再利用可能にする

記録項目：

- 目的、問い、仮説
- 利用データと版、取得条件
- 品質上の制約と補正
- 分析手順、除外、判断基準
- 意思決定者と決定内容
- 実施結果と効果
- 失敗、想定外、副作用
- 次回の改善事項

成功事例だけでなく失敗事例も残します。個人の失敗追及ではなく、再発防止と組織学習に使います。

## 確認問題（本書オリジナル）

販促後に売上が10%増えました。施策成功と判断する前に確認すべき事項を挙げてください。

**解答例：** 比較期間、季節性、価格変更、他施策、対象顧客、利益、返品、在庫切れ、データ品質、事前に定めた成功基準を確認します。売上増加が施策によるものか、利益や長期効果を損ねていないかを検証します。

## まとめ

- 分析結果を課題と結び付け、要因候補・示唆・対応案を区別する。
- 実行前に成功条件と測定方法を定める。
- 結果と意思決定過程を記録し、次回へ教訓を引き継ぐ。
