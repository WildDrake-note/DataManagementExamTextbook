# 第10章 意思決定と継続的改善

## 学習目標

- 分析結果を課題、要因、示唆、対応案へ結び付けられる。
- 分析結果と示唆を、注意点も含めて関係者へ説明できる。
- 重要度、緊急度、期待効果、実現可能性で対応案を比較できる。
- 目標値と実績値の差を定量・定性の両面から検証し、改善へつなげられる。
- 分析条件と意思決定過程を再利用可能に記録し、教訓を共有できる。

**シラバス対応**：科目A「業務分析」、科目B 2-3～2-5。

## 1. 分析結果を意思決定につなげる

「解約率が8%だった」は分析結果です。その数値だけでは、何が問題で、何をすべきかは決まりません。洞察とは、分析結果を業務課題と結び付け、考えられる要因、解決策への示唆、利用上の注意点を整理したものです。

```text
業務課題
  │  「何を改善したいか」
  ▼
分析結果 ──→ 解釈 ──→ 要因候補 ──→ 示唆 ──→ 対応案 ──→ 意思決定
  │             │          │          │          │
  │             │          │          │          └─ 誰が、いつ、何をするか
  │             │          │          └─ 実行可能な選択肢
  │             │          └─ 解決の方向性
  │             └─ 因果とは限らない
  └─ 対象・期間・条件を明示
```

各段階を混同すると、分析結果から性急に施策へ飛び付いてしまいます。

| 段階 | 問い | 解約分析の例 | 表現上の注意 |
|---|---|---|---|
| 結果 | データから何が分かったか | 特定プランの契約初月の解約率が他プランより高い | 対象、期間、分母を添える |
| 解釈 | 業務上どのような意味か | 初月の顧客体験に課題がある可能性がある | 観測事実と解釈を分ける |
| 要因候補 | なぜ起きた可能性があるか | 導入説明不足、期待との不一致、初期設定の難しさ | 相関だけで原因と断定しない |
| 示唆 | どの方向を詳しく調べるか | 初月支援と契約時説明を重点的に見直す | 反証や追加調査も示す |
| 対応案 | 具体的に何をするか | オンボーディング面談を一部顧客で試す | 費用、担当、リスクを示す |

### 反証を探す

自分の仮説に合う事実だけを集めると、確証バイアスが生じます。「初月支援不足が原因」という仮説なら、支援を受けても解約した顧客、支援なしでも継続した顧客、価格改定や競合キャンペーンの影響も確認します。反証可能性を残すことは、結論を弱くするのではなく、意思決定の信頼性を高めます。

## 2. 関係者に説明して共通理解を作る

説明の目的は、分析の詳しさを示すことではなく、関係者が同じ前提で判断できるようにすることです。次の順序で説明すると、結論と根拠の関係が伝わりやすくなります。

1. **課題と判断事項**：誰が何を決めるのか。
2. **対象と方法**：対象データ、期間、範囲、品質、集計・分析方法。
3. **主な結果**：比較対象や基準値を添えた数値。
4. **解釈と示唆**：業務上の意味、要因候補、反証。
5. **注意点**：欠損、偏り、未取得データ、不確実性。
6. **対応案**：期待効果、費用、リスク、実行条件。
7. **判断依頼**：承認、追加調査、保留など、求める判断。

### 職場例：配送遅延の報告

物流担当者が「北部地域の遅延率は12%です」とだけ報告しても、管理者は行動を選べません。次のように整理します。

> 過去3か月の通常便を調べたところ、北部地域では遅延率が全社4%に対して12%でした。遅延の70%は金曜夕方に集中しています。積雪日を除いても傾向は残りますが、委託先の積載記録が一部欠損しているため、積載超過が原因とはまだ断定できません。まず4週間、金曜便を1便増やし、遅延率と追加費用を比較することを提案します。

この説明は、結果、比較、要因候補、限界、対応案を区別しています。

## 3. 対応案の優先順位

複数案があるときは、評価観点を先に合意します。点数は議論を可視化する道具であり、機械的に決定する装置ではありません。

| 観点 | 問い | 確認できる情報の例 |
|---|---|---|
| 重要度 | 解決しない場合の影響は大きいか | 顧客数、損失額、安全・信用への影響 |
| 緊急度 | 期限や被害拡大の可能性はあるか | 法令期限、繁忙期、障害の拡大速度 |
| 期待効果 | 課題指標をどの程度改善できるか | 過去実績、試行結果、類似事例 |
| 実現可能性 | 人、費用、技術、権限を確保できるか | 工数、予算、データ、承認経路 |
| リスク | 法務、倫理、品質、運用への副作用は何か | 個人情報、誤判定、現場負荷 |
| 可逆性 | 失敗時に停止し元へ戻せるか | 対象限定、ロールバック手順 |

### 必須条件と比較条件を分ける

法令違反や安全上の重大リスクは、期待効果の高得点で相殺できません。まず満たすべき必須条件で候補を絞り、その後に比較条件で順位を付けます。

```text
候補案
  │
  ├─ 必須条件を満たすか（法令・安全・社内規程・最低品質）
  │       ├─ いいえ → 除外又は条件を見直す
  │       └─ はい
  ▼
比較条件で評価（重要度・緊急度・期待効果・実現可能性など）
  ▼
依存関係と不確実性を確認
  ▼
実行順序・担当・期限を決定
```

### 職場例：三つの在庫改善案

| 案 | 期待効果 | 実現可能性 | 主なリスク | 判断例 |
|---|---|---|---|---|
| 発注点を一括変更 | 高い可能性 | 高い | 欠品増加 | 一部商品で試行 |
| 需要予測システムを全面導入 | 高い | 低い | 費用、導入期間 | PoC後に再判断 |
| 長期滞留品を可視化 | 中程度 | 高い | 小さい | 直ちに実施 |

全面導入の期待効果が最大でも、すぐ着手できるとは限りません。短期の可視化と、限定的な試行を並行させるなど、実行順序も意思決定の一部です。

## 4. AI分析結果の妥当性確認

AIを用いた場合も、最終的な業務判断の責任がAIへ移るわけではありません。業務担当者は少なくとも次を確認し、専門的なモデル評価が必要ならデータサイエンティストやデータ主管組織と協働します。

| 確認対象 | 確認例 |
|---|---|
| 利用データ | 範囲、対象期間、項目、欠損、偏り、最新版か |
| 集計・前処理 | 除外条件、重複処理、カテゴリ統合、外れ値処理 |
| 分析前提 | 予測対象、基準時点、利用目的に合う評価指標 |
| 出力整合性 | 合計と内訳、既知事例、元データとの突合 |
| 業務妥当性 | 現場知識と大きく矛盾しないか、例外を扱えるか |
| リスク | 誤判定時の影響、偏った扱い、説明可能性、人の確認 |

例えば、AIが「残業時間の長い社員は退職しやすい」と示しても、残業を退職の原因と断定してはいけません。職種、勤務地、勤続年数などの交絡要因や、退職直前の引継ぎによる残業増加も考えられます。AIの説明は要因候補として扱い、人事上の不利益な判断へ直結させないことが重要です。

## 5. 取組結果の検証

実行前に成功条件を定めます。結果を見てから基準を変えると、都合のよい評価になり、次回の比較もできません。

| 設計項目 | 内容 | コールセンター施策の例 |
|---|---|---|
| 基準値 | 実施前の状態 | 平均保留時間180秒 |
| 目標値 | 達成したい状態 | 12週間で150秒以下 |
| 測定対象 | 誰・何を測るか | 対象3チームの全通話 |
| 比較対象 | 何と比べるか | 未導入の類似2チーム |
| 副作用指標 | 改善と引換えに悪化しないか | 再入電率、苦情率、担当者負荷 |
| 見直し条件 | いつ中止・修正するか | 苦情率が2週連続で基準値を超える |

### 目標と実績の差を分解する

未達を「施策が悪かった」で終わらせず、どこで差が生じたかを調べます。

```text
目標未達
  ├─ 仮説の問題：想定した要因が主要因ではなかった
  ├─ 設計の問題：対象・期間・目標が不適切だった
  ├─ 実行の問題：研修不足、利用率不足、手順逸脱があった
  ├─ 測定の問題：定義変更、欠損、比較条件の差があった
  └─ 外部要因　：繁忙期、価格改定、制度変更が重なった
```

未達でも、仮説が否定されたことや実行上の障害が分かったことは学習成果です。ただし、「学びがあった」というだけで継続を正当化せず、追加費用に見合うかを再判断します。

## 6. 定量・定性の両面で業務変化を見る

定量情報は変化の大きさや広がりを比較しやすく、定性情報は数値だけでは分からない理由や体験を把握しやすいという違いがあります。

| 情報 | 強み | 注意点 | 例 |
|---|---|---|---|
| 定量 | 程度、頻度、推移を比較できる | 定義や母集団が不適切だと誤る | 処理時間、誤入力率、売上 |
| 定性 | 背景、理由、想定外を把握できる | 少数の印象を全体へ一般化しやすい | 観察、面談、自由記述 |

処理時間が20%短縮しても、入力担当者が別作業を肩代わりしている、顧客への説明が省略されて再問い合わせが増えている可能性があります。数値と現場観察を突き合わせ、同じ方向を示すか、食い違いの理由は何かを確認します。

## 7. 教訓を再利用可能にする

再利用できる記録には、結果だけでなく「どの条件で、なぜそう判断したか」が必要です。

- 目的、問い、仮説
- 利用データと版、取得条件、データオーナー
- 品質上の制約と補正
- 分析手順、除外条件、判断基準
- 得られた示唆と注意点
- 意思決定者、選択肢、決定理由
- 実施結果、定量・定性の効果
- 失敗、想定外、副作用
- 適用できる条件、適用できない条件
- 次回の改善事項と担当

成功事例だけでなく失敗事例も残します。共有の目的は個人の失敗追及ではなく、同じ失敗を避け、次の分析を速くすることです。固有の顧客情報や人事情報は必要以上に共有せず、権限管理された保管場所を使います。

### 教訓の記録例

| 項目 | 記録例 |
|---|---|
| 仮説 | FAQ検索を改善すれば問い合わせ処理時間が短縮する |
| 結果 | 検索利用者では短縮したが、新人は検索語を選べず未改善 |
| 意思決定 | 全社展開を保留し、新人向け候補語を追加する |
| 再利用条件 | 商品コードを理解する担当者には有効 |
| 次回 | 新人群を分けて評価し、検索失敗率も測定する |

## 確認問題（本書オリジナル）

### 問1

販促後に売上が10%増えました。施策成功と判断する前に確認すべき事項を挙げてください。

**解答例：** 比較期間、季節性、価格変更、他施策、対象顧客、利益、返品、在庫切れ、データ品質、事前に定めた成功基準を確認します。売上の増加だけでは販促との因果や利益への貢献を示せないためです。「10%増えたので成功」と即断するのは、外部要因と副作用を無視するため不適切です。結果を見て成功基準を10%に設定するのも、評価基準の後付けになるため不適切です。

### 問2

AIが、解約要因の第1位を「問い合わせ回数」と出力しました。業務担当者が次に行うべき確認を説明してください。

**解答例：** 対象期間、問い合わせ回数の定義、欠損・重複、解約前後の時間関係、顧客属性などの交絡要因、既知事例との整合性を確認し、必要に応じてデータ主管組織や分析担当者へ相談します。問い合わせ回数は不満の原因ではなく、不具合の結果である可能性もあるためです。「AIの順位どおり問い合わせを減らす」のは、因果を未確認のまま顧客支援を制限するため不適切です。「現場感覚と違うので結果を捨てる」のも、反証調査をせず有用な兆候を失うため不適切です。

### 問3

作業時間20%短縮を目標にした施策で、実績は15%短縮でした。現場からは「入力ミスが増えた」との声があります。どのように評価し、改善へつなげますか。

**解答例：** 目標との差5ポイントだけでなく、対象別の利用状況、手順の実施率、入力ミス率、修正時間、現場観察を確認します。その上で、操作手順や入力チェックを改善して再測定するか、影響が大きければ施策を停止します。主指標が未達で副作用もあるため、総合評価が必要です。「15%短縮したので成功」とするのは品質悪化を無視するため不適切です。「20%に届かなかったので即廃止」も、実行上の改善で効果が得られる可能性を調べていないため不適切です。

## まとめ

- 分析結果を課題と結び付け、要因候補・示唆・対応案を区別する。
- 関係者には、根拠だけでなく不確実性と判断事項も説明する。
- 対応案は必須条件を確認してから、重要度、緊急度、期待効果などで比較する。
- 実行前に成功条件と測定方法を定め、定量・定性の両面から結果を検証する。
- 結果と意思決定過程を記録し、成功と失敗の教訓を次回へ引き継ぐ。
