# 第10章 意思決定と継続的改善

## 学習目標

- 分析結果を課題、要因、示唆、対応案へ結び付けられる。
- 分析結果と示唆を、注意点も含めて関係者へ説明できる。
- 重要度、緊急度、期待効果、実現可能性で対応案を比較できる。
- 目標値と実績値の差を定量・定性の両面から検証し、改善へつなげられる。
- 分析条件と意思決定過程を再利用可能に記録し、教訓を共有できる。

**シラバス対応**：科目A「業務分析」、科目B 2-3～2-5。

## 1. 分析結果を意思決定につなげる

「解約率が8%だった」は分析結果です。その数値だけでは、何が問題で、何をすべきかは決まりません。洞察とは、分析結果を業務課題と結び付け、考えられる要因、解決策への示唆、利用上の注意点を整理したものです。

```text
業務課題
  │  「何を改善したいか」
  ▼
分析結果 ──→ 解釈 ──→ 要因候補 ──→ 示唆 ──→ 対応案 ──→ 意思決定
  │             │          │          │          │
  │             │          │          │          └─ 誰が、いつ、何をするか
  │             │          │          └─ 実行可能な選択肢
  │             │          └─ 解決の方向性
  │             └─ 因果とは限らない
  └─ 対象・期間・条件を明示
```

各段階を混同すると、分析結果から性急に施策へ飛び付いてしまいます。

| 段階 | 問い | 解約分析の例 | 表現上の注意 |
|---|---|---|---|
| 結果 | データから何が分かったか | 特定プランの契約初月の解約率が他プランより高い | 対象、期間、分母を添える |
| 解釈 | 業務上どのような意味か | 初月の顧客体験に課題がある可能性がある | 観測事実と解釈を分ける |
| 要因候補 | なぜ起きた可能性があるか | 導入説明不足、期待との不一致、初期設定の難しさ | 相関だけで原因と断定しない |
| 示唆 | どの方向を詳しく調べるか | 初月支援と契約時説明を重点的に見直す | 反証や追加調査も示す |
| 対応案 | 具体的に何をするか | オンボーディング面談を一部顧客で試す | 費用、担当、リスクを示す |

### 反証を探す

自分の仮説に合う事実だけを集めると、確証バイアスが生じます。「初月支援不足が原因」という仮説なら、支援を受けても解約した顧客、支援なしでも継続した顧客、価格改定や競合キャンペーンの影響も確認します。反証可能性を残すことは、結論を弱くするのではなく、意思決定の信頼性を高めます。

### 証拠から洞察までの推論を見える化する

洞察は「数字を見た感想」ではありません。観測事実、そこから導く主張、両者をつなぐ業務知識、残る代替説明を明示した推論です。同じ証拠でも前提が違えば主張が変わるため、推論の橋渡し部分をレビュー可能にします。

| 要素 | 問うこと | 解約分析の記述例 |
|---|---|---|
| 証拠 | 直接観測・計算した事実は何か | 初月解約率は対象群12%、比較群7% |
| 主張 | 証拠から何を述べるか | 対象群には初月離脱の課題がある |
| 推論根拠 | なぜ証拠が主張を支えるのか | 契約開始月と顧客属性をそろえても差が残る |
| 代替説明 | 他に何が同じ結果を生むか | 販売経路、価格、障害発生率の違い |
| 不確実性 | どの程度確かで何が未確認か | 一部経路の説明記録が欠損している |
| 次の判断 | 何を決めるための証拠か | 全面変更でなく、一部経路で説明改善を試す |

```text
観測データ ──品質・比較可能性──> 証拠
                                  │
                      業務知識・仮定を明示
                                  ▼
                               主張
                         ┌────────┴────────┐
                         ▼                 ▼
                    代替説明を探す    反証データを探す
                         └────────┬────────┘
                                  ▼
                        確度付きの洞察と次の判断
```

証拠が弱い場合も、意思決定を停止するだけが選択肢ではありません。可逆的な小規模試行、追加調査、監視付き導入など、証拠の確度に合う行動を選べます。反対に、証拠が弱いのに不可逆な全面展開を行うのは、リスクと確度が釣り合っていません。

## 2. 関係者に説明して共通理解を作る

説明の目的は、分析の詳しさを示すことではなく、関係者が同じ前提で判断できるようにすることです。次の順序で説明すると、結論と根拠の関係が伝わりやすくなります。

1. **課題と判断事項**：誰が何を決めるのか。
2. **対象と方法**：対象データ、期間、範囲、品質、集計・分析方法。
3. **主な結果**：比較対象や基準値を添えた数値。
4. **解釈と示唆**：業務上の意味、要因候補、反証。
5. **注意点**：欠損、偏り、未取得データ、不確実性。
6. **対応案**：期待効果、費用、リスク、実行条件。
7. **判断依頼**：承認、追加調査、保留など、求める判断。

### 職場例：配送遅延の報告

物流担当者が「北部地域の遅延率は12%です」とだけ報告しても、管理者は行動を選べません。次のように整理します。

> 過去3か月の通常便を調べたところ、北部地域では遅延率が全社4%に対して12%でした。遅延の70%は金曜夕方に集中しています。積雪日を除いても傾向は残りますが、委託先の積載記録が一部欠損しているため、積載超過が原因とはまだ断定できません。まず4週間、金曜便を1便増やし、遅延率と追加費用を比較することを提案します。

この説明は、結果、比較、要因候補、限界、対応案を区別しています。

## 3. 対応案の優先順位

複数案があるときは、評価観点を先に合意します。点数は議論を可視化する道具であり、機械的に決定する装置ではありません。

| 観点 | 問い | 確認できる情報の例 |
|---|---|---|
| 重要度 | 解決しない場合の影響は大きいか | 顧客数、損失額、安全・信用への影響 |
| 緊急度 | 期限や被害拡大の可能性はあるか | 法令期限、繁忙期、障害の拡大速度 |
| 期待効果 | 課題指標をどの程度改善できるか | 過去実績、試行結果、類似事例 |
| 実現可能性 | 人、費用、技術、権限を確保できるか | 工数、予算、データ、承認経路 |
| リスク | 法務、倫理、品質、運用への副作用は何か | 個人情報、誤判定、現場負荷 |
| 可逆性 | 失敗時に停止し元へ戻せるか | 対象限定、ロールバック手順 |

### 必須条件と比較条件を分ける

法令違反や安全上の重大リスクは、期待効果の高得点で相殺できません。まず満たすべき必須条件で候補を絞り、その後に比較条件で順位を付けます。

```text
候補案
  │
  ├─ 必須条件を満たすか（法令・安全・社内規程・最低品質）
  │       ├─ いいえ → 除外又は条件を見直す
  │       └─ はい
  ▼
比較条件で評価（重要度・緊急度・期待効果・実現可能性など）
  ▼
依存関係と不確実性を確認
  ▼
実行順序・担当・期限を決定
```

### 職場例：三つの在庫改善案

| 案 | 期待効果 | 実現可能性 | 主なリスク | 判断例 |
|---|---|---|---|---|
| 発注点を一括変更 | 高い可能性 | 高い | 欠品増加 | 一部商品で試行 |
| 需要予測システムを全面導入 | 高い | 低い | 費用、導入期間 | PoC後に再判断 |
| 長期滞留品を可視化 | 中程度 | 高い | 小さい | 直ちに実施 |

全面導入の期待効果が最大でも、すぐ着手できるとは限りません。短期の可視化と、限定的な試行を並行させるなど、実行順序も意思決定の一部です。

## 4. AI分析結果の妥当性確認

AIを用いた場合も、最終的な業務判断の責任がAIへ移るわけではありません。業務担当者は少なくとも次を確認し、専門的なモデル評価が必要ならデータサイエンティストやデータ主管組織と協働します。

| 確認対象 | 確認例 |
|---|---|
| 利用データ | 範囲、対象期間、項目、欠損、偏り、最新版か |
| 集計・前処理 | 除外条件、重複処理、カテゴリ統合、外れ値処理 |
| 分析前提 | 予測対象、基準時点、利用目的に合う評価指標 |
| 出力整合性 | 合計と内訳、既知事例、元データとの突合 |
| 業務妥当性 | 現場知識と大きく矛盾しないか、例外を扱えるか |
| リスク | 誤判定時の影響、偏った扱い、説明可能性、人の確認 |

例えば、AIが「残業時間の長い社員は退職しやすい」と示しても、残業を退職の原因と断定してはいけません。職種、勤務地、勤続年数などの交絡要因や、退職直前の引継ぎによる残業増加も考えられます。AIの説明は要因候補として扱い、人事上の不利益な判断へ直結させないことが重要です。

## 5. 取組結果の検証

実行前に成功条件を定めます。結果を見てから基準を変えると、都合のよい評価になり、次回の比較もできません。

| 設計項目 | 内容 | コールセンター施策の例 |
|---|---|---|
| 基準値 | 実施前の状態 | 平均保留時間180秒 |
| 目標値 | 達成したい状態 | 12週間で150秒以下 |
| 測定対象 | 誰・何を測るか | 対象3チームの全通話 |
| 比較対象 | 何と比べるか | 未導入の類似2チーム |
| 副作用指標 | 改善と引換えに悪化しないか | 再入電率、苦情率、担当者負荷 |
| 見直し条件 | いつ中止・修正するか | 苦情率が2週連続で基準値を超える |

### 目標と実績の差を分解する

未達を「施策が悪かった」で終わらせず、どこで差が生じたかを調べます。

```text
目標未達
  ├─ 仮説の問題：想定した要因が主要因ではなかった
  ├─ 設計の問題：対象・期間・目標が不適切だった
  ├─ 実行の問題：研修不足、利用率不足、手順逸脱があった
  ├─ 測定の問題：定義変更、欠損、比較条件の差があった
  └─ 外部要因　：繁忙期、価格改定、制度変更が重なった
```

未達でも、仮説が否定されたことや実行上の障害が分かったことは学習成果です。ただし、「学びがあった」というだけで継続を正当化せず、追加費用に見合うかを再判断します。

### 反実仮想を置いて効果を考える

施策後の実績と施策前の実績の差には、施策効果だけでなく、季節性、市況、他施策、対象構成の変化が含まれます。知りたい効果は「施策を実施した実績」と「同じ対象に同じ時点で施策を実施しなかったなら得られたはずの結果」の差です。後者を**反実仮想**といいますが、同じ対象では同時に観測できないため、無作為化した対照群、類似した比較群、過去傾向などで推定します。

| 比較方法 | 反実仮想の置き方 | 主な注意点 |
|---|---|---|
| 前後比較 | 施策前の値が続いたとみなす | 季節性や同時期の外部変化を分離しにくい |
| 対照群比較 | 未実施群の同時期の変化を使う | 群の選ばれ方や施策波及の影響を確認する |
| 無作為化比較 | 無作為に割り付けた未実施群を使う | 実施可能性、倫理、標本数、群間干渉に注意する |
| 差の差 | 実施群と比較群の前後変化の差を使う | 施策がなければ平行に変化したという仮定を確認する |

**業務例：検品研修の効果検証**

研修対象ラインの不良率は18%から12%へ6ポイント低下しました。同時期に未受講の類似ラインも10%から8%へ2ポイント低下しています。単純な前後比較では効果を6ポイントとしますが、全社的な原材料改善などで2ポイント下がった可能性があります。差の差で推定すると、`(12%－18%)－(8%－10%) = -4` ポイントです。施策がなければ対象ラインも16%程度になったと考え、研修の追加的な低下を4ポイントと推定します。1,000件当たりなら不良40件の減少に相当します。

この4ポイントも無条件の因果効果ではありません。施策前の両ラインの傾向が似ていたか、製品構成や検査基準が変わっていないか、研修内容が比較群へ共有されていないかを確認します。また、不良率だけでなく検品時間、手直し費、見逃し率という副作用も測ります。

### 効果、実行、測定を分けて診断する

施策が効かなかったのか、施策が実施されなかったのか、測定できなかったのかは別問題です。主指標だけでなく、実行状況を示すプロセス指標を組み合わせます。

| 層 | 指標例 | 分かること |
|---|---|---|
| 入力 | 研修時間、配布数、投入費用 | 計画した資源を投入したか |
| 実行 | 受講率、機能利用率、手順遵守率 | 施策が対象へ届き、実施されたか |
| 直接結果 | 知識テスト、処理時間、一次解決率 | 直近の行動や業務が変わったか |
| 最終成果 | 不良率、利益、解約率 | 解決したい課題が改善したか |
| 副作用 | 苦情、再作業、現場負荷 | 別の場所へ問題を移していないか |

例えば解約率が改善せず、面談実施率が20%なら、「面談は無効」とはまだいえません。まずなぜ実施されなかったかを調べます。一方、実施率95%でも改善せず、比較条件と測定に問題がなければ、仮説や施策内容の見直しが中心になります。

## 6. 定量・定性の両面で業務変化を見る

定量情報は変化の大きさや広がりを比較しやすく、定性情報は数値だけでは分からない理由や体験を把握しやすいという違いがあります。

| 情報 | 強み | 注意点 | 例 |
|---|---|---|---|
| 定量 | 程度、頻度、推移を比較できる | 定義や母集団が不適切だと誤る | 処理時間、誤入力率、売上 |
| 定性 | 背景、理由、想定外を把握できる | 少数の印象を全体へ一般化しやすい | 観察、面談、自由記述 |

処理時間が20%短縮しても、入力担当者が別作業を肩代わりしている、顧客への説明が省略されて再問い合わせが増えている可能性があります。数値と現場観察を突き合わせ、同じ方向を示すか、食い違いの理由は何かを確認します。

## 7. 教訓を再利用可能にする

再利用できる記録には、結果だけでなく「どの条件で、なぜそう判断したか」が必要です。

- 目的、問い、仮説
- 利用データと版、取得条件、データオーナー
- 品質上の制約と補正
- 分析手順、除外条件、判断基準
- 得られた示唆と注意点
- 意思決定者、選択肢、決定理由
- 実施結果、定量・定性の効果
- 失敗、想定外、副作用
- 適用できる条件、適用できない条件
- 次回の改善事項と担当

成功事例だけでなく失敗事例も残します。共有の目的は個人の失敗追及ではなく、同じ失敗を避け、次の分析を速くすることです。固有の顧客情報や人事情報は必要以上に共有せず、権限管理された保管場所を使います。

### 教訓の記録例

| 項目 | 記録例 |
|---|---|
| 仮説 | FAQ検索を改善すれば問い合わせ処理時間が短縮する |
| 結果 | 検索利用者では短縮したが、新人は検索語を選べず未改善 |
| 意思決定 | 全社展開を保留し、新人向け候補語を追加する |
| 再利用条件 | 商品コードを理解する担当者には有効 |
| 次回 | 新人群を分けて評価し、検索失敗率も測定する |

### 意思決定記録を残す

分析報告書が「何が分かったか」を中心にするのに対し、意思決定記録は「その時点で何を選び、なぜ選んだか」を残します。後から結果だけを見て過去の判断を評価する結果バイアスを避けるため、決定時点の情報、不確実性、却下案も記録します。

| 記録項目 | 記録する内容 | 再利用上の価値 |
|---|---|---|
| 決定事項 | 採用案、対象範囲、開始日、責任者 | 実行内容の曖昧さを防ぐ |
| 判断目的 | 改善する指標と期限 | 手段が目的化するのを防ぐ |
| 根拠 | 使用データ、分析結果、現場情報 | 後から根拠の妥当性を再確認できる |
| 仮定・不確実性 | 未取得データ、外部要因、確度 | 結果が違った理由を検討できる |
| 比較した選択肢 | 採用・却下理由、何もしない案 | 同じ議論の繰返しを減らす |
| ガードレール | 中止条件、副作用指標、承認条件 | 被害を限定し、可逆性を確保する |
| 再評価日 | いつ、誰が、何を見て再判断するか | 放置や惰性的継続を防ぐ |

記録は決定を固定する契約ではありません。新しい証拠で変更した場合は、元の記録を書き換えて履歴を消すのではなく、変更理由と新しい決定を追記します。

### 検証を一回で終わらせない学習ループ

```text
課題を定義
    ↓
仮説と反証条件を置く
    ↓
小さく実行 ──→ 実行状況を監視
    ↓                 │
効果・副作用を比較 ←─┘
    ↓
意思決定記録を更新
    ├─ 継続・拡大
    ├─ 修正して再試行 ──┐
    └─ 停止・別仮説へ ──┴─→ 次の課題定義
```

学習ループでは、成功時にも「どの条件で再現するか」を問い、失敗時にも「仮説、実行、測定のどこが崩れたか」を分けます。指標の改善が一時的でないかを追跡し、対象を拡大すると顧客構成や現場能力が変わる点も再評価します。

## 8. 感度・シナリオ分析で意思決定ポートフォリオを組む

案を一件ずつ順位付けするだけでは、同じ人員を奪い合う競合、先に必要な基盤、複数案で重複する効果を見落とします。意思決定ポートフォリオでは、案の組合せと実行順序を選び、全体の効果、下振れ、資源制約、学習価値を管理します。

| 観点 | 確認する問い | ポートフォリオへの反映 |
|---|---|---|
| 感度 | どの仮定が少し変わると結論が逆転するか | 重要仮定を追加調査・監視する |
| シナリオ | 弱気・基準・強気で各案の結果はどう変わるか | 平均だけでなく下振れ幅も比較する |
| 依存関係 | 先に完了すべきデータ、承認、技術は何か | 前提案を先行し、ゲートを置く |
| 競合・相乗 | 人員の奪い合い、効果の重複・増幅はあるか | 単純な効果の足し算を避ける |
| 可逆性 | 停止、縮小、元へ戻す費用と時間はどれほどか | 不確実なら小さく試して選択権を残す |
| 不可逆性 | 契約、設備、信用など回復困難な影響はあるか | 高い証拠水準と承認ゲートを要求する |

```text
候補案と「何もしない」を列挙
             │
       依存関係・資源競合を結ぶ
             ▼
  弱気 ── 基準 ── 強気シナリオで評価
             │
      重要仮定の感度を確認
             ▼
┌─ 可逆案：小さく開始 → 観測 → 拡大／停止
└─ 不可逆案：前提案 → 承認ゲート → 段階投資
             │
      組合せ全体の効果と下振れを再評価
```

感度分析は一つの入力を変えて結論の頑健性を調べ、シナリオ分析は需要、費用、供給制約など整合する複数条件をまとめて変えます。精密な確率がないときは無理に期待値へ一本化せず、各シナリオで許容できるか、撤退条件を満たすかを示します。確率を付ける場合も、その根拠と更新日を記録します。

**計算例：在庫改善三案の組合せ**

純効果を百万円単位で見積もり、弱気・基準・強気の確率を25%・50%・25%とします。Aはデータ品質の可視化、Bは自動発注、Cは手作業レビューです。

| 案 | 弱気 | 基準 | 強気 | 期待純効果 | 可逆性・依存関係 |
|---|---:|---:|---:|---:|---|
| A 可視化 | 1 | 3 | 4 | 2.75 | 可逆。Bの前提 |
| B 自動発注 | -4 | 3 | 8 | 2.50 | 切替後は戻しにくい。A完了が必要 |
| C 手作業レビュー | 1 | 2 | 2 | 1.75 | 可逆。Bと同じ担当者を使う |

期待純効果は、例えばBなら `-4×0.25＋3×0.50＋8×0.25=2.50` 百万円です。A+Cは単純合計で4.50百万円、A+Bは5.25百万円ですが、A+Bの弱気時は `1－4=-3` 百万円です。期待値だけならA+Bが上でも、不可逆なBを直ちに開始する必要はありません。まずAを実施し、欠損率と発注誤差が基準を満たした場合だけBへ進むゲートを置けば、Aから情報を得て下振れを限定できます。

確率の感度も調べます。弱気60%、基準25%、強気15%へ変えると、Bの期待純効果は `-4×0.60＋3×0.25＋8×0.15=-0.45` 百万円となり、判断が逆転します。したがって需要下振れの確率は重要仮定です。一方、Cは撤回しやすく短期の損失を抑えますが、担当者がBの準備と競合するため、A+B+Cの値を機械的に合算してはいけません。

可逆・不可逆は二択ではなく、対象地域の限定、短期契約、段階発注、ロールバック手順によって変えられます。各ゲートで利用する証拠、判断者、期限、中止条件を意思決定記録へ残し、状況変化時にはポートフォリオ全体を組み替えます。

## 9. 追加調査の価値と待つコストを比べる

不確実なら常に調査を増やせばよいわけではありません。情報は、結果によって採用・中止などの行動を変えられるときに価値を持ちます。追加調査による期待純効果の改善から、調査費用と判断を待つ機会損失を差し引きます。

| 比較項目 | 確認すること |
|---|---|
| 現時点の最善案 | 今決める場合の行動と期待純効果 |
| 調査結果別の行動 | 良い結果と悪い結果で判断を変えるか |
| 情報価値 | 調査後に最適行動を選ぶ期待値と、調査せず現時点の最善行動を選ぶ期待値との差 |
| 調査費用 | 試行、データ取得、分析、現場対応の費用 |
| 待つコスト | 売上逸失、被害拡大、期限超過 |
| 決定期限 | 調査結果が間に合う最終時点 |

```text
[不確実な判断]
   +-- 今決める ----------------> [現時点の最善案]
   |
   +-- 追加調査
          +-- 結果で行動が変わる --> [情報価値を計算]
          +-- 何が出ても同じ行動 --> [調査価値は小さい]
                                      |
                    情報価値－費用－待つコストで判断
```

**計算例：小規模調査を待つか**

新サービスを開始したときの純効果を、需要が高ければ6百万円、低ければ－5百万円とし、現在の確率を60%と40%とします。今開始する期待純効果は `6×0.60－5×0.40=1.60` 百万円なので、調査なしでは開始が最善です。

50万円の調査後、良い結果が出る確率は60%で、その場合に高需要である確率は80%とします。良い結果後に開始する期待値は `6×0.80－5×0.20=3.80` 百万円です。悪い結果後に高需要である確率は30%で、開始の期待値は `6×0.30－5×0.70=-1.70` 百万円になるため、開始しない0百万円を選びます。調査後に最適行動を選べる期待値は `3.80×0.60＋0×0.40=2.28` 百万円です。

情報価値の基準は「何もしない場合」ではなく、**調査せずに現時点で選べる最善行動**です。この例では現時点の最善行動が開始で期待純効果1.60百万円なので、調査の情報価値は `2.28－1.60=0.68` 百万円、費用差引後は0.18百万円です。調査を待つ損失が18万円を超えるなら、他の条件が同じ場合、調査は見合いません。確率と金額は推定なので、根拠と感度を示し、人命・法令・権利など金額だけで決められない条件は別の必須基準として扱います。

## 10. 便益台帳で価値実現と継続・停止を管理する

施策を導入したことと、価値を実現したことは別です。企画時の期待便益を実績へ自動的に置き換えず、誰が便益を業務で実現するか、どの費用を差し引くか、いつ拡大・修正・停止を判断するかを**便益台帳**で管理します。プロジェクト責任者が納品を完了しても、業務手順や要員配置を変えなければ、短縮された時間は実際の費用削減や処理能力向上につながらない場合があります。

| 管理項目 | 決める内容 | 主な責任者 |
|---|---|---|
| 便益定義 | 金額、時間、品質、リスク低減のどれを価値とするか | 便益オーナー（業務責任者） |
| 基準値・比較 | 導入前の値、比較群、対象量、季節性 | 分析担当・データオーナー |
| 実現行動 | 廃止する作業、再配置する時間、変更する業務手順 | 便益オーナー |
| 帰属・重複 | 他施策や外部要因をどう分け、同じ便益の二重計上を防ぐか | 分析担当・財務担当 |
| 継続費用 | 利用料、確認、監視、教育、例外処理を含めるか | 財務担当・運用責任者 |
| 判断境界 | 拡大、修正、停止に必要な値と評価期間 | 意思決定者 |
| 再評価 | 確認日、証拠、未達時の担当と期限 | 意思決定者・便益オーナー |

```text
[期待便益と実現仮説]
          v
[基準値・費用・便益オーナーを固定]
          v
[実行] --> [利用・業務変更を確認] --> [実現便益を測定]
                                             |
                +----------------------------+-------------------------+
                v                            v                         v
        [拡大基準を達成]             [修正範囲にある]          [停止条件に該当]
          拡大を判断                  期限付きで修正             停止・資源再配分
                \___________________________  _________________________/
                                            \/
                              [便益台帳と次回判断を更新]
```

**職場例：重複受注チェックを継続するか**

受注部門は、重複による手直しが月200件、1件当たり4,000円かかる状態を基準値としました。チェック機能の導入後は月80件となったため、同じ対象量と重大度を仮定した回避便益は `(200－80)×4,000=480,000` 円です。一方、月額利用料と監視に26万円、追加確認に6万円かかり、月間実現純便益は `48万円－26万円－6万円=16万円` でした。

導入前に、月間純便益20万円以上なら対象を拡大、0円超20万円未満なら費用又は確認手順を1か月以内に修正、0円以下が2か月続けば停止すると決めていました。今回は精度達成だけを理由に拡大せず、便益オーナーが確認対象の絞込みを試し、翌月に再判断します。既に支払った初期費用は取り戻せないため、継続判断では将来の追加便益と追加費用を比較します。

この判断は、導入前後で受注量と案件の難しさが比較可能で、減った手直しが別工程へ移っておらず、空いた時間を他業務へ使えるという仮定に依存します。失敗しやすいのは、作業時間の全てを現金削減とみなす、他施策の効果を重複計上する、運用・確認費を除外する、責任者のいない「年間効果」を掲げる、初期投資が大きいことを理由に未達施策を続ける場合です。仮定が崩れたときは基準値と帰属を見直し、便益が実現していない事実を隠さず停止を選択肢に戻します。

## 確認問題（本書オリジナル）

### 問1

販促後に売上が10%増えました。施策成功と判断する前に確認すべき事項を挙げてください。

**解答例：** 比較期間、季節性、価格変更、他施策、対象顧客、利益、返品、在庫切れ、データ品質、事前に定めた成功基準を確認します。売上の増加だけでは販促との因果や利益への貢献を示せないためです。「10%増えたので成功」と即断するのは、外部要因と副作用を無視するため不適切です。結果を見て成功基準を10%に設定するのも、評価基準の後付けになるため不適切です。

### 問2

AIが、解約要因の第1位を「問い合わせ回数」と出力しました。業務担当者が次に行うべき確認を説明してください。

**解答例：** 対象期間、問い合わせ回数の定義、欠損・重複、解約前後の時間関係、顧客属性などの交絡要因、既知事例との整合性を確認し、必要に応じてデータ主管組織や分析担当者へ相談します。問い合わせ回数は不満の原因ではなく、不具合の結果である可能性もあるためです。「AIの順位どおり問い合わせを減らす」のは、因果を未確認のまま顧客支援を制限するため不適切です。「現場感覚と違うので結果を捨てる」のも、反証調査をせず有用な兆候を失うため不適切です。

### 問3

作業時間20%短縮を目標にした施策で、実績は15%短縮でした。現場からは「入力ミスが増えた」との声があります。どのように評価し、改善へつなげますか。

**解答例：** 目標との差5ポイントだけでなく、対象別の利用状況、手順の実施率、入力ミス率、修正時間、現場観察を確認します。その上で、操作手順や入力チェックを改善して再測定するか、影響が大きければ施策を停止します。主指標が未達で副作用もあるため、総合評価が必要です。「15%短縮したので成功」とするのは品質悪化を無視するため不適切です。「20%に届かなかったので即廃止」も、実行上の改善で効果が得られる可能性を調べていないため不適切です。

### 問4

新しい検品手順を導入したラインでは不良率が18%から12%へ低下し、未導入の類似ラインでも同期間に10%から8%へ低下しました。施策の効果をどのように考え、意思決定記録へ何を残すべきですか。

**解答例：** 単純な前後差は6ポイント低下ですが、比較ラインの2ポイント低下を差し引く差の差では、追加効果は `(12－18)－(8－10) = -4` ポイント、すなわち4ポイントの低下と推定します。施策前の傾向、製品構成、検査基準、他施策、群間の情報共有を確認し、検品時間や見逃し率も評価します。記録には採用・継続の判断、対象、根拠データ、平行傾向などの仮定、代替案、中止条件、責任者、再評価日を残します。

**理由：** 施策後の改善全てが施策効果とは限らず、同時期の共通要因を反実仮想に反映する必要があるためです。また、決定時点の仮定と不確実性を残せば、後から結果だけで判断の良否を決めず、次の試行へ学びを移せます。**不適切な考え方：** 「18%から12%なので効果は必ず6ポイント」は共通要因を無視しています。「比較群も改善したので施策効果はゼロ」も誤りで、実施群は比較群よりさらに4ポイント改善しています。

## まとめ

- 分析結果を課題と結び付け、要因候補・示唆・対応案を区別する。
- 関係者には、根拠だけでなく不確実性と判断事項も説明する。
- 対応案は必須条件を確認してから、重要度、緊急度、期待効果などで比較する。
- 実行前に成功条件と測定方法を定め、定量・定性の両面から結果を検証する。
- 結果と意思決定過程を記録し、成功と失敗の教訓を次回へ引き継ぐ。
- 追加調査は、情報によって行動が変わるかを確かめ、情報価値から費用と待つコストを差し引いて判断する。
- 便益オーナー、実現行動、全継続費用、判断境界を便益台帳に残し、実現純便益に基づいて拡大・修正・停止を判断する。
