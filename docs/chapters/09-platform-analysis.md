# 第9章 データ基盤と分析基礎

## 学習目標

- データレイク、DWH、データマートの役割を比較できる。
- 目的から問い・仮説・必要データを整理できる。
- 基本的な統計・可視化を選び、相関と因果を区別できる。
- 分析前にデータの生成背景、品質、比較可能性を確認できる。

**シラバス対応**：科目A・重点分野「データ分析・データ利活用」、科目B 2-1、2-2。

## 1. データ基盤

データ基盤は、データの蓄積、加工、分析、提供を支える仕組みです。

| 概念 | 主な特徴 |
|---|---|
| データレイク | さまざまな形式のデータを比較的元の形で蓄積する |
| DWH | 分析目的に合わせて統合・整理したデータを蓄積する |
| データマート | 特定部門・用途向けに必要なデータを提供する |
| データ仮想化 | データを物理的に集約せず、統合的なアクセスを提供する |
| データファブリック | 分散したデータをメタデータや自動化で横断的に管理・提供する考え方 |

名称だけで優劣は決まりません。目的、鮮度、容量、品質、権限、費用、運用能力を考慮します。

ETLは抽出後に変換して格納し、ELTは抽出・格納後に変換します。処理順序が違っても、変換ルール、品質検査、リネージ、失敗時対応が必要です。

## 2. 分析・管理ツール

- **BIツール**：集計、ダッシュボード、可視化を支援する。
- **セルフサービス分析**：業務利用者が自ら探索・分析する。自由度とともに定義・権限・品質の統制が必要。
- **データプレパレーション**：分析前の整形、結合、品質確認を支援する。
- **データブレンディング**：複数ソースを分析用途で組み合わせる。
- **セマンティックレイヤー**：業務用語・指標と物理データの間に共通の意味層を設ける。
- **オントロジー**：概念と関係を形式的に表現し、意味の共有や推論を助ける。

## 3. 課題から問いへ

「売上を増やしたい」は広すぎます。検証可能な問いへ変えます。

- 課題：特定商品の売上が前年より減った。
- 問い：減少は客数、購入率、単価のどれによるか。
- 仮説：新規顧客の購入率低下が主因である。
- 必要データ：顧客区分、訪問、購入、商品、価格、期間。
- 判断：どの程度の差なら施策対象とするか。

問いを先に定めないと、使いやすいデータだけを眺め、後から都合のよい物語を作りやすくなります。

## 4. データの選定

- 内部・外部の所在とオーナー
- 取得可能性、費用、期間
- 利用権限と目的
- 粒度、範囲、生成背景
- 品質と更新頻度
- 比較可能性
- 代替データと限界

外部公開データでも、定義変更や調査方法を確認します。一次データは自らの目的で収集したデータ、二次データは別目的で収集されたデータを再利用するものです。二次データは生成背景の確認が特に重要です。

## 5. 記述統計

- **平均**：全値の合計を件数で割る。外れ値の影響を受けやすい。
- **中央値**：順序の中央。偏った分布で代表値として有用。
- **最頻値**：最も多く現れる値。
- **分散・標準偏差**：値のばらつきを表す。
- **箱ひげ図**：中央値、四分位範囲、外れ値候補を可視化する。
- **クロス集計**：カテゴリの組合せ別に件数・割合を比較する。

分母と母集団を常に確認します。件数増加と割合増加は同じではありません。

## 6. 相関、因果、バイアス

二つの変数がともに変動しても、一方が他方の原因とは限りません。第三の要因、逆因果、偶然を検討します。

- **選択バイアス**：対象の選ばれ方による偏り。
- **情報バイアス**：測定・記録方法による偏り。
- **交絡**：第三の変数が原因と結果の両方に関係する。
- **確証バイアス**：自分の仮説に合う情報を重視する。

仮説検定は「差が実務上重要か」を自動的に答えません。統計的不確実性と業務上の効果を分けて評価します。

## 7. 可視化

目的に合う図を選びます。

- 推移：折れ線図
- 項目比較：棒グラフ
- 分布：ヒストグラム、箱ひげ図
- 二変数関係：散布図
- 構成：積み上げ棒など（円グラフは多数項目に不向き）
- 地理：地図、シェープファイルを用いた表示
- 二軸分類：ヒートマップ

軸の切断、面積や3D効果、恣意的な期間選択で誤解を招かないようにします。

## 確認問題（本書オリジナル）

店舗別売上と店舗別従業員数に強い正の相関がありました。「従業員を増やせば売上が増える」と直ちに結論できない理由を説明してください。

**解答例：** 店舗規模や来客数が両方を増やす交絡要因かもしれず、売上が大きいから従業員を増やした逆因果も考えられます。期間、店舗規模、施策、選定方法を確認し、必要なら追加分析や検証を行います。

## まとめ

- 基盤は蓄積だけでなく、品質・意味・権限・提供を支える。
- 課題を検証可能な問いと仮説へ変えてからデータを選ぶ。
- 統計値と可視化は前提・分母・バイアスを確認して解釈する。
