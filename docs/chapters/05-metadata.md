# 第5章 メタデータ管理

## 学習目標

- ビジネス、テクニカル、オペレーショナルメタデータを区別できる。
- データ辞書、ビジネスグロッサリー、データカタログの関係を説明できる。
- メタデータの登録・更新・品質管理に業務部門の参加が必要な理由を説明できる。

**シラバス対応**：科目A・重点分野「メタデータ管理」、科目B 1-1、1-4。

## 1. メタデータはデータを利用可能にする説明

列名が `CST_STS_CD` で値が `3` でも、利用者は意味を判断できません。「顧客状態コード」「3は休眠」「毎日更新」「営業企画部が責任者」といった説明があって初めて利用できます。メタデータはデータの探索、理解、品質確認、安全利用、再利用を支えます。

## 2. 三つの分類

| 分類 | 例 | 主な利用者 |
|---|---|---|
| ビジネスメタデータ | 業務用語、指標定義、利用目的、責任者、利用条件 | 業務担当者、分析者 |
| テクニカルメタデータ | テーブル・列名、型、桁、主外部キー、変換仕様 | 開発者、データエンジニア |
| オペレーショナルメタデータ | 作成・更新日時、処理件数、ジョブ結果、容量 | 運用担当者、品質管理者 |

分類は相互に関連します。業務上の「有効顧客」という指標が、どのテーブル・列・計算式で実現され、いつの処理で更新されたかをつなぐと説明可能性が高まります。

## 3. 管理の仕組み

### データ辞書

データ項目名、意味、型、桁、コード、制約などを整理します。対象が物理項目中心か論理項目中心かは組織により異なります。

### ビジネスグロッサリー

売上、顧客、契約開始などの業務用語を統一し、定義、同義語、計算条件、責任者を管理します。同じ語の複数定義が必要な場合は、適用範囲を明示します。

### データカタログ

データセットを検索し、意味、所在、所有者、品質、利用条件、リネージなどを確認する入口です。自動収集できる技術情報と、人が判断して登録する業務情報を組み合わせます。

### メタデータレジストリ／リポジトリ

レジストリは標準化された定義や識別を管理する仕組み、リポジトリはメタデータを格納・提供する基盤という観点で使われます。実際の製品名称より、何を統制し何を提供するかを確認します。

## 4. データリネージ

リネージは、データの生成元、変換、結合、提供先を追跡する情報です。次に役立ちます。

- 誤りがどのレポートへ影響したかを調べる。
- 指標の計算根拠を説明する。
- 仕様変更の影響範囲を把握する。
- 個人情報などの複製先を追跡する。

自動取得だけでは、業務上の意味や手作業の補正が抜けることがあります。重要な手動工程も記録します。

## 5. 管理プロセス

1. 対象、必須項目、登録責任者、承認、更新頻度を決める。
2. システムから技術・運用情報を収集する。
3. 業務部門が意味、ルール、責任者を登録・確認する。
4. 変更時にメタデータを更新する。
5. 完全性、正確性、最新性、利用状況を測定する。
6. 古い定義や不明な所有者を改善する。

カタログ導入は管理の開始であって完成ではありません。業務部門が参加せず、意味の記述や更新責任が曖昧なら、検索できても信頼できない一覧になります。

## 6. メタデータ品質

確認例：

- 必須説明が登録された割合
- オーナー不明のデータセット数
- 更新期限を超過した項目数
- 定義と実データの形式が一致する割合
- 利用条件や機密区分が登録された割合
- 問い合わせ・利用回数

登録数だけでなく、利用者がデータを正しく選び、安全に使えるかを評価します。

## 確認問題（本書オリジナル）

IT部門が全テーブルと列名を自動収集してカタログへ登録しました。しかし営業担当者は必要なデータを選べません。最も考えられる不足は何ですか。

**解答例：** 顧客、商談、売上などの業務上の意味、適用範囲、利用条件、データオーナーといったビジネスメタデータが不足しています。業務部門の参画と継続更新が必要です。

## まとめ

- メタデータはデータの探索・理解・統制・再利用を支える。
- 技術情報の自動収集だけでは、業務上の意味を整備できない。
- 登録後も責任者、更新契機、品質指標を定めて継続管理する。
