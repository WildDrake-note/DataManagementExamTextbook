# 第11章 組織文化と協働

## 学習目標

- データ活用の意義を業務改善・意思決定・価値創出と関連付けて説明できる。
- 部門ごとの要望と制約を整理し、共通理解を作れる。
- 成功・失敗事例から得た知見を組織へ共有できる。

**シラバス対応**：科目B 3-1、3-2。

## 1. ツールだけでは文化は変わらない

BIツールやデータ基盤を導入しても、指標定義が部門で異なる、失敗を共有できない、データの責任が不明、利用者が結果を信用しない状態では活用は定着しません。組織文化は、日々の会議、評価、役割、行動、学習の積み重ねで形成されます。

## 2. データ活用の意義

- 経験や直感を否定するのではなく、検証可能な根拠を加える。
- 業務の状況と変化を可視化する。
- 仮説と結果を比較し、改善速度を上げる。
- 部門間で共通の事実認識を作る。
- 顧客・社会への価値とリスクを説明可能にする。

データドリブンは「数字だけで決める」ことではありません。データの限界を理解し、業務知識、倫理、戦略と合わせて判断します。

## 3. 関係者の視点

| 関係者 | 主な関心 |
|---|---|
| 経営・業務責任者 | 効果、リスク、優先順位、説明責任 |
| 業務担当者 | 実態との一致、作業負担、使いやすさ |
| データ主管組織 | 標準、品質、所有者、全社最適 |
| IT部門 | 実装、運用、セキュリティ、費用 |
| 法務・コンプライアンス | 法令、契約、権利、社会的影響 |
| 分析担当者 | データの意味、品質、分析可能性 |

対立を「データ活用への抵抗」と片付けず、制約の背景を確認します。

## 4. 共通理解を作る対話

1. 解決したい業務課題を共有する。
2. 用語、指標、対象、粒度を確認する。
3. 必要なデータと所有者を特定する。
4. セキュリティ、法務、作業負担、品質の制約を整理する。
5. 役割、判断者、期限を決める。
6. 小さく試し、結果と教訓を共有する。

会議で数字が違う場合、すぐに正誤を争うのではなく、定義、期間、分母、更新時点、除外条件を比較します。

## 5. 成功・失敗事例の共有

共有内容は「成果が出た」だけでは不十分です。

- 課題と対象業務
- 仮説と選定データ
- 前提、品質、制約
- 実施内容と役割分担
- 結果と測定方法
- 想定外、失敗、副作用
- 再利用できる条件
- 次回の改善

成功条件を示さず結果だけを横展開すると、別部門では再現しない可能性があります。

## 6. 定着のための仕組み

- データオーナーと相談窓口を明確にする。
- グロッサリーとカタログを日常業務へ組み込む。
- 品質問題を報告しやすくする。
- 会議資料で指標定義と出所を示す。
- 研修だけでなく実務課題を使った演習を行う。
- 活用事例と失敗から得た教訓を蓄積する。
- 作業負担や統制の効果を定期的に見直す。

## 確認問題（本書オリジナル）

営業部と経理部の月次売上が一致しません。協働の第一歩として行うことを説明してください。

**解答例：** 受注・出荷・請求・入金のどの時点を売上とするか、対象期間、取消・返品、税、更新時点、粒度を比較します。各数値の目的と責任者を明確にし、必要なら用途別の定義としてグロッサリーへ登録します。

## まとめ

- データ文化は、ツールではなく役割・対話・日常行動で定着する。
- 部門差は、目的・定義・制約を明示して調整する。
- 成功と失敗の条件を記録し、再利用可能な組織知にする。
