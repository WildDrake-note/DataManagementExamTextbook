# 第3章 データガバナンス

## 学習目標

- データガバナンスの目的と基本行動を説明できる。
- CDO、DMO、データオーナー、データスチュワード、IT部門、利用者の役割を区別できる。
- 問題発見、暫定対応、恒久対応、メタデータ更新の責任を判断できる。

**シラバス対応**：科目A・重点分野「データガバナンス」、科目B 1-2～1-4、3-2。

## 1. ガバナンスは意思決定の仕組み

データガバナンスは、データに関する方針、意思決定権、責任、監視、エスカレーションを明確にする仕組みです。目的は利用を止めることではなく、価値創出とリスク管理を両立させることです。

基本行動は、概念的に次の循環で捉えられます。

1. **評価**：現状、価値、リスク、遵守状況を把握する。
2. **方針・指示**：原則、ルール、責任、優先順位を定める。
3. **監視**：実施状況と結果を確認し、必要なら是正する。

## 2. 主な役割

| 役割 | 主な責任 |
|---|---|
| CDO | 全社データ戦略・ガバナンスの統括 |
| DMO | 方針・標準の整備、部門支援、調整、監視 |
| データオーナー | 対象データの定義、品質、利用条件に関する意思決定と説明責任 |
| データスチュワード | 定義・品質・メタデータを日常的に維持する実務 |
| データアーキテクト | 全体構造、モデル、データフローの設計 |
| データエンジニア | 収集・変換・提供基盤の実装・運用 |
| IT部門 | システム、権限、可用性など技術面の運用 |
| データ利用者 | 利用条件の遵守、目的適合性の確認、問題報告 |

名称だけで判断してはいけません。組織ごとの規程で実際の責任と権限を確認します。

## 3. 責任と作業を混同しない

カタログシステムをIT部門が運用していても、業務用語の意味をIT部門が決めるとは限りません。一般に、プラットフォームの稼働責任と、掲載内容の正しさに対する責任は分けて考えます。

同様に、利用部門が分析用にデータを独自加工した場合、元データの品質責任は元のオーナーに残る一方、加工結果やレポートについては加工した部門が説明責任を負うことがあります。判断は組織ルールに従います。

## 4. 問題対応の流れ

### 発見・記録

期待する定義と実データの差、影響範囲、再現条件を記録します。「データがおかしい」だけでは対処できません。

### 報告・エスカレーション

対象データのオーナーや定められた窓口へ報告します。漏えいや重大な法令違反の疑いは、通常の品質改善とは別の緊急ルールに従います。

### 暫定対応

業務期限に対応するため、一時的な補正、対象除外、注記付き利用などを行います。前提、影響、承認、適用範囲を記録し、恒久対策の代替にしません。

### 恒久対応

入力ルール、コード体系、システム制御、責任分担、教育など、発生原因へ対処します。

### メタデータ更新

定義や許容値が誤っていた場合はカタログ等を更新します。ただし、実データの誤りに合わせて定義を安易に書き換えてはいけません。どちらが正しい規範かを確認します。

## 5. 組織構造

- **中央集権型**：全社組織が標準と意思決定を集中管理する。一貫性を得やすいが、現場対応が遅くなる可能性がある。
- **分散型**：各部門が広い裁量を持つ。専門性と速度を得やすいが、重複・不統一が生じやすい。
- **連邦型**：全社共通原則と部門裁量を組み合わせる。境界と調整方法の設計が重要になる。

唯一の正解はありません。組織規模、規制、データ共有の必要性に応じて設計します。

## 確認問題（本書オリジナル）

販売データの「地域コード」に未定義値が見つかりました。分析担当者は締切のため未定義値を「その他」へ一時変換しました。適切な責任分担を説明してください。

**解答例：** 分析担当者は変換規則、影響、前提を記録し、加工結果への説明責任を負います。元データのオーナーは原因を確認し、入力・連携・コード管理の恒久対策を主導します。カタログの定義が誤っていれば、その管理責任者が正式な承認を経て更新します。

## まとめ

- ガバナンスは、意思決定権と説明責任を明確にする。
- システム運用者、内容責任者、加工者の責任は同じとは限らない。
- 暫定対応と恒久対応を分け、問題・判断・影響を記録する。
